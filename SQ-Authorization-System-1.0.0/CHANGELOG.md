## 一、界面与交互

### 1.1 修复 Windows 深色模式下的整条黑带（影响全部四个程序）

- **现象**：系统处于深色模式时，服务器设置面板、验证端页面、管理端/主控端页面以及
  AI 助手聊天区，滚动过程中会出现一条贯穿面板宽度的纯黑横带；卡顿时更明显。
- **根因**：滚动区的内容层背景是完全透明的（截图采样为 `#000000`、alpha=0）。
  Qt 滚动时只重绘“新露出的那一条”，透明层不落任何像素，这条带就保持未绘制状态；
  再叠加 Windows 11 原生风格会按系统深色主题绘制未被样式覆盖的子控件（滚动视口、
  滚动条角落、弹出框边缘），于是白界面里冒出黑块/黑带。
- **修复**：
  - `core/theme.py`：滚动区自身、视口（`#qt_scrollarea_viewport`）与滚动内容层全部改为
    **不透明页面底色**；新增 `QWidget#ScrollBody`、`QTabWidget::pane`、`QTabBar` 的背景规则。
  - 启动时强制浅色 `QPalette`，并在 Windows 上统一切换 `Fusion` 样式（`SQ_KEEP_NATIVE_STYLE=1`
    可回退到系统原生风格），使配色完全由本项目的样式表决定。
  - 标题栏与窗口边框通过 DWM（`DwmSetWindowAttribute`）强制浅色，避免“白界面 + 黑边”。
  - `server/ui.py`、`verification/ui.py`、`core/ai_page.py`：三处滚动区改为实底并开启视口自填充。
- **回归防护**：新增 `tests/test_theme_dark_mode.py`（深色调色板被覆盖、滚动无黑带、
  四个端的滚动内容层均不透明共 3 条用例）与扫描工具 `tools/dark_mode_sweep.py`
  （遍历四个端所有页面与所有滚动位置，统计近黑像素带）。

### 1.2 服务器 exe 不再挂着一个黑色控制台窗口

- 本地服务器是唯一以控制台模式打包的 exe（无界面模式需要控制台输出），此前双击进入
  图形界面时，旁边会一直留着一个黑色控制台窗口。
- 现在双击运行时自动隐藏该控制台；**从 cmd / Windows Terminal 启动时不会隐藏你的终端**
  （通过 `GetConsoleProcessList` 判断控制台是否由本程序独占），需要控制台时可用
  `--show-console` 强制保留。
- 实现：`core/winconsole.py`、`server/main.py`；用例 `tests/test_winconsole.py`（4 条）。

### 1.3 管理端与主控端界面区分

- 此前两端界面几乎一致，管理端也能看到管理员相关入口。现在明确分离：
  - **管理端 = 密钥运营**：系统概览、AI 助手、告警中心、生成密钥、密钥管理、用户管理、
    批次管理、离线激活、审计日志、修改密码、关于。
  - **主控端 = 系统管理**：在上述基础上额外拥有「管理员管理」与「系统设置」。
- 侧边栏新增角色标识与配色区分，窗口标题也写明角色。

### 1.4 登录与首次引导体验

- 验证端「邮箱登录」、管理端、主控端、服务器登录处新增 **「记住账号」「记住密码」**；
  勾选记住密码会自动锁定记住账号。

- 服务器首次运行的引导弹窗新增 **「复制账号」「复制密码」** 独立按钮（保留整体复制）。

### 1.5 验证端用户资料

### 1.6 用户管理界面

- 修复“管理端与主控端读不到邮箱注册用户、没有对应用户菜单”的问题。

### 1.7 稳定性相关的界面修复

- 修复服务器界面定时刷新在数据库已关闭时仍触发导致的报错（刷新失败只记日志、自动停表）。
- 修复 Qt 事件过滤器在控件销毁后仍被调用导致的异常连锁
  （曾表现为 `SystemError: Error calling Python override of QObject::eventFilter()`）。
- 服务器界面刷新周期由 3 秒调整为 10 秒，审计日志只预览最近 50 条，降低空闲占用。

  `faulthandler` / Qt 消息处理器），日志写入 `crash_logs/`。

## 二、邮箱账号与邮件系统

### 2.1 账号体系

- **管理员账号邮箱**：主控端「管理员管理」可为账号绑定邮箱并输入验证码完成验证；登录框新增
  「忘记密码」，通过邮箱验证码重置密码（重置后强制改密并失效旧登录态）。
- **验证端邮箱登录**：与「激活码登录」并列，顶部可切换。支持注册、登录、忘记密码、
  绑定并激活、校验、请求续费、脱绑、退出。
- **绑定规则**：一个邮箱同一时间只能绑定一个 Key；Key 仍有效时禁止自助脱绑（返回 409），
  过期/吊销/次数用尽后可自助脱绑并释放设备；Key 失效后可续费或脱绑后重新订阅。

### 2.2 SMTP 与邮件模板

- SMTP 配置项：主机、端口、用户名、密码、发件邮箱、发件人名称、STARTTLS、SSL、超时、
  管理员告警收件人，配置**保存即生效**（无需重启）。
- 保存时校验：SSL 与 STARTTLS 互斥、用户名/密码成对、发件人必填；坏配置不允许保存。
- 「发送测试邮件」直接发送并弹出可读的错误原因（含 503/535/550 处理建议）。
- **7 个内置邮件模板**：邮箱验证码、重置密码、完整性告警、风控告警、续费请求、
  告警规则通知、测试邮件；模板存数据库，可改文案，模板变量 `{{变量名}}` 渲染时做 HTML 转义。

### 2.3 邮件队列与投递

- 所有通知先写 `email_outbox`，后台工作线程每 5 秒投递；失败按指数退避重试（最多 5 次后
  进入 dead），不阻塞业务请求；投递记录可通过 `GET /api/email/outbox` 查看。
- 增加 `claimed_at` 租约：进程崩溃导致长期卡在 `sending` 的邮件会被回收重投；
  投递成功与状态落库拆开处理，避免“已发送但落库失败”造成重复发送。
- 收件人规则：触发 Key 的绑定邮箱 + 管理员告警收件邮箱 + 已绑定并验证邮箱的管理员账号；
  都没有时静默跳过并在事件里标记未通知。

### 2.4 已修复的邮件故障

- **`503 need EHLO and AUTH first`**：发送状态机改为严格按
  EHLO →（STARTTLS 后重新 EHLO）→ AUTH → MAIL FROM 执行；用户名缺省时使用发件邮箱。
- **每封邮件卡 12 秒**：修复 `socket.getfqdn()` 本机反向解析阻塞，改为显式
  `local_hostname` + `make_msgid(domain=...)`。
- 使用提示：QQ/163/企业邮箱需填写**授权码**而不是网页登录密码；465 端口勾 SSL，
  587 端口勾 STARTTLS，两者不能同时开。

## 三、告警中心与通知渠道

### 3.1 告警中心（管理端 / 主控端）

新增「告警中心」导航，含四个页签：

- **告警规则**：7 个内置指标 —— 激活率(%)、在线并发(台)、过期率(%)、7 天内到期(个)、
  激活失败(次)、风控事件(次)、完整性告警(次)；每条规则可配置运算符（≥、＞、≤、＜）、
  阈值、统计窗口、级别、冷却时间、通知渠道与启停。
- **告警事件**：触发中 / 已确认 / 已处理三种状态，支持筛选、确认、标记已处理，15 秒自动刷新；
  同一规则同时只保留一个活动事件，指标恢复后自动转为已恢复，冷却期内不重复触发。
- **通知渠道**：Webhook、钉钉、企业微信、飞书四种渠道的增删改查、测试发送与投递记录。
- **投递记录**：渠道投递状态、失败原因与重试次数。

### 3.2 通知投递

- 邮件走 `email_outbox`，其它渠道走 `channel_outbox`，均后台投递、指数退避重试、
  最多 5 次后进入 dead，不阻塞请求。
- Webhook 自动附带 `X-SQ-Signature: sha256=<hmac>` 签名头；钉钉、飞书支持官方加签；
  企业微信与飞书返回 `errcode/code` 非 0 时按失败处理并记录原因。
- 规则可同时勾选「邮件」与任意已启用渠道；无收件人/未启用时事件仍落库并标记未通知。

### 3.3 内置风控规则

- **新硬件码抢占设备位**：检测到新硬件码顶掉已满的设备位时，冻结该 Key 并发送邮件告警。
- **IP 频繁跳动**：同一 Key 在 10 分钟内出现超过 2 个 IP 网段时发送告警；阈值与窗口可通过
  `server_config.json → security.ip_jump_window_minutes`、`ip_jump_alert_threshold` 调整。
- **完整性告警**：可执行文件校验失败或出现未知发布哈希时告警并记录事件。

## 四、授权、密钥与离线激活

- **批量生成**：支持分钟卡 / 小时卡 / 天卡 / 次数卡 / 长期等时长单位，多版本、多批次、
  指定绑定设备数上限，生成后可导出。
- **批量操作**：批量续期、批量冻结/解冻、批量吊销/恢复、批量删除；执行期间弹出模态进度框、
  禁用主要按钮并加互斥标志，防止重复进入导致重复执行。
- **导出**：卡密与列表支持 CSV / TXT 导出（导出单元格做 CSV 注入防护，导出量大时有上限提示）；
  服务器端支持导出审计日志。
- **设备绑定**：硬件码绑定、解绑、换机；`max_devices` 限制同一 Key 可绑定的设备数量，
  达到上限的抢占会触发风控（见上）。
- **离线激活**：设备端生成离线请求码（`LICREQ1.` 前缀，含机器码）→ 管理员在「离线激活」
  页生成 Ed25519 签名的离线激活码 → 设备端导入激活；请求码/激活码支持分段显示与保存为文件。
- **心跳校验**：心跳请求带 HMAC 签名与 nonce 防重放。
- **验证端可脱离发布文件运行**：缺少 `release_manifest.json` / 签名时进入独立运行模式
  （不弹窗、不退出），用于把你自己的软件与验证端一起打包分发；文件存在但被篡改仍拒绝启动。

## 五、发布完整性与防篡改

- **签名清单**：构建时生成 `release_manifest.json` + Ed25519 签名 `release_manifest.sig`，
  每次构建生成新的 `release_id`（写入程序内部），清单包含四个 exe 的路径、大小与 SHA256。
- **启动门禁**：exe 必须与清单、签名同目录；文件被修改、缺失、目录里多出未登记的 `.exe/.dll`、
  签名不匹配、`release_id` 与程序内置值不一致 —— 任一情况都会**弹窗提示 + 写
  `integrity_tamper.log` + 拒绝启动**，并尽力上报服务器。
- **服务端校验**：服务器启动时验签并导入清单到发布白名单；激活/校验/心跳必须携带
  `X-Attest-Token`，未知或被篡改的客户端返回 403「客户端完整性校验未通过，已拒绝访问」，
  事件写入 `tamper_events` 并出现在审计日志。
- **修复通道**：提供 `--repair-manifest <发布包目录>`，在清单损坏时验签 + 核对 exe 哈希 +
  原子写回；哈希不符仍然拒绝（fail closed）。
- **版本退役**：导入新清单时旧版本记录自动失效，避免新旧混用。
- **发行包卫生检查**：构建时自动检查组内是否混入运行配置、数据库或私钥，发现即构建失败。

## 六、安全加固

- **密钥与开发数据外移**：服务器私钥、HMAC 密钥、发布签名私钥、开发数据库整体移出仓库与
  发行包（备份在本地 `backup_secrets_20261008/`，不入库）；构建重新生成密钥；
  `dist/` 不再作为分发目录。
- **修复历史隐患**：旧发行包里 `dist/admin_config.json` 固定的响应公钥与服务端不一致
  （会导致管理端必然登录失败）、`dist/data/license.db` 携带开发数据（含 master 账号）——
  发行包现在只包含 4 个 exe + 签名清单 + `releases/`。
- **SDK 完整性豁免默认关闭**：开启后仍需配置 `sdk_shared_secret` 并携带
  `X-SDK-Token = HMAC(secret, machine_code)`，放行写审计日志。
- **通知渠道地址防护**：默认拒绝指向私网/回环/链路本地/保留地址与 localhost 的渠道地址，
  内网 Webhook 需显式开启 `security.channel_allow_private_hosts=true`。
- **头像解码炸弹防护**：校验 PNG/JPEG/WebP 魔术字节与头部尺寸，拒绝超过 4096×4096 或 16MP 的图片。
- **审计日志净化**：统一剥离控制字符并限制长度，避免日志被换行/控制字符污染。
- **登录防护**：账号级与来源 IP 级双重限流；未知账号同样执行完整口令哈希，避免通过响应
  耗时枚举账号。
- **口令存储**：`PBKDF2-SHA256` 600,000 次迭代并带版本标识（旧库 120,000 次哈希仍可登录）。
- **文件权限**：配置文件与数据库写入后尽力收紧本机访问权限（POSIX `chmod 600`；
  Windows 用 `icacls` 移除继承）。
- **队列一致性**：邮件/渠道 outbox 增加租约与终态回收，避免崩溃后丢信或重复发送。

## 七、性能与稳定性

- 统计结果 5 秒缓存；过期扫描 60 秒节流；补齐热点查询索引。
- 审计日志计数缓存（30 秒、最多 32 组筛选条件），降低界面周期开销。
- 邮件与渠道工作线程在空队列时不再抢占数据库写锁。
- 服务器界面刷新由 3 秒改为 10 秒，日志预览限制 50 条。
- 修复每封邮件因本机反向解析卡 12 秒的问题（见邮件章节）。
- 修复告警引擎与渠道分发线程在重启时的重复投递问题（每次运行独立停止事件）。
- 高频定时器加护栏：服务器刷新、验证端心跳、日志页自动刷新出现异常只记日志不中断。
- 新增性能基准工具 `tools/bench_server.py`。

## 八、AI 助手

- **写操作两阶段确认**：AI 的写类工具默认返回 `pending_confirmation` 与 120 秒有效的
  HMAC 确认令牌；确认/取消通过 `/api/ai/confirm`、`/api/ai/cancel` 完成，令牌一次性消费、
  绑定操作人并写审计；客户端显示确认条。
- **任务取消与有界退出**：轮询以 0.2 秒粒度检查取消事件，窗口关闭时停止任务，
  服务端退出有上限，避免卡死。
- 告警指标按窗口缓存，同一周期内多条规则共享同一份计算结果。

## 九、工程、测试与文档

- **测试**：49 个测试文件，`python -m pytest -q` → 524 passed + 12 subtests passed。

## 发布与使用注意

- 对外**只分发** `dist/release_package/`：4 个 exe + `release_manifest.json` +
  `release_manifest.sig` + `releases/`。
- 替换时**必须整套一起换**：只换 exe 而保留旧清单会触发完整性门禁，启动被直接拒绝并写入
  `integrity_tamper.log`。
- 发布签名私钥 `release_keys/release_key.json` 必须离线备份；泄露等于泄露签名能力。
- 远程部署请配置 HTTPS/受信证书，并把 `--print-public-key` 导出的响应公钥固定到客户端；
  远程明文 HTTP 会被客户端拒绝。
- 忘记主控密码时不要删数据库：`本地服务器.exe --reset-master-password` 会重新生成一次性
  密码并保留全部授权数据。
